# Задание на создание скилла 1 — `product-vision`

**Дата:** 2026-05-31
**Контекст продукта (пример):** платформа оценки рисков (risk assessment).
**Важно:** это ТЗ на разработку скилла. Сам скилл по этому документу пока **не создаётся**.

---

## Место в цепочке

```
[Product Vision]  →  Бизнес-архитектура  →  ИТ-архитектура
   (зачем)              (что)                 (как)
```

Это **первый** скилл цепочки. Его выход является входом для скилла `business-architecture`.
Принцип: выход предыдущего этапа = вход следующего; предусмотрена обратная связь снизу вверх.

---

## Спецификация

**Назначение:** сформировать продуктовое видение из стратегического контекста.

**Триггеры:** «сформулируй видение продукта», «product vision», «куда движется продукт».

**Вход:**
- Стратегия компании, цели бизнеса/акционеров
- Боли и потребности рынка (исследования, интервью)
- Анализ конкурентов и регуляторного ландшафта
- Тренды (технологические, рыночные)
- Ограничения: бюджет, сроки, аппетит к риску

**Выход:**
- Формулировка видения (1–2 предложения)
- Целевые сегменты и value proposition
- Долгосрочные продуктовые цели и North Star метрики
- Продуктовые принципы и ограничения

**Acceptance criteria:**
- На выходе всегда есть North Star метрика и хотя бы один явный принцип/ограничение
- Выход структурирован так, чтобы его можно было передать в `business-architecture`

---

## Handoff schema (контракт передачи)

Каждый элемент выхода оформляется как запись со сквозными полями (общий контракт для всех скиллов цепочки):

| Поле | Назначение |
|------|------------|
| `id` | Уникальный идентификатор (напр. `VIS-001`, `GOAL-002`, `PRIN-001`) |
| `type` | vision / goal / metric / principle / segment |
| `text` | Содержание |
| `trace_up` | Ссылка на источник (стратегия/рынок/регулятор) |
| `status` | draft / approved |
| `owner` | Кто approve (стейкхолдер) |
| `version` | Версия артефакта |

Эти `id` далее используются в `business-architecture` (`trace_up`) и в матрице трассируемости.

---

## Output template (шаблон выхода)

```
## Видение
{1–2 предложения}                                   [VIS-001]

## Целевые сегменты и value proposition
- {сегмент} → {ценность}                            [SEG-00X]

## Цели и North Star метрики
| id | Цель | North Star метрика | trace_up |
|----|------|--------------------|----------|

## Принципы и ограничения (non-negotiable)
- {принцип/ограничение}                             [PRIN-00X]

## Non-goals (что продукт сознательно НЕ делает)
- ...

## Допущения и открытые вопросы
- {что не хватило на входе / что предполагаем}
```

---

## Few-shot пример (продукт «оценка рисков»)

```
## Видение
Дать риск-менеджерам решение по контрагенту за минуты, а не дни —
с прозрачной и объяснимой оценкой риска.                         [VIS-001]

## Цели и North Star метрики
| id      | Цель                      | North Star метрика        | trace_up        |
| GOAL-01 | Сократить цикл решения    | Время оценки ≤ 5 мин      | рынок: «дни»    |
| GOAL-02 | Доверие к решению         | % решений с объяснением   | регулятор       |

## Принципы и ограничения
- Объяснимость модели обязательна (без «чёрного ящика»)          [PRIN-01]

## Non-goals
- Не строим розничный скоринг физлиц на этом этапе

## Допущения и открытые вопросы
- Предполагаем доступ к внешним источникам данных о контрагенте (уточнить)
```

---

## Definition of Done

- Есть видение, ≥1 North Star метрика (измеримая), ≥1 принцип, секция non-goals.
- Все элементы имеют `id` и `trace_up`.
- Заполнен раздел «Допущения и открытые вопросы».

## Anti-scope (что скилл НЕ делает)

- Не описывает процессы и capabilities (это `business-architecture`).
- Не выбирает технологии и системы (это `it-architecture`).

---

## Маппинг на SDD (Spec-Driven Development)

| Этот скилл | Этап SDD |
|------------|----------|
| Принципы/ограничения, non-goals | **Constitution** |
| Видение, цели, метрики | **Specify** (что и зачем, без «как») |

Выход скилла = верхняя часть спецификации SDD-конвейера, продолжается в `business-architecture`.

---

## Общие требования

- Язык вывода: русский.
- Результат структурирован (таблицы/списки), пригоден как вход следующего скилла.
- Версионирование артефакта + changelog при изменениях.
- Демо-пример для проверки: сквозной прогон на продукте «оценка рисков».

## Что НЕ входит

- Реализация самого скилла (создаётся отдельно, по этому ТЗ).
- Привязка к конкретной отрасли — базовая версия универсальна.
