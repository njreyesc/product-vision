## Видение

Дать кредитному аналитику и риск-менеджеру **разговорного агента по конкретной сделке**,
который за минуты выдаёт **короткое объяснимое заключение** (кто/что/зачем пришёл + выводы,
риски и бенефициар), а полное рассуждение раскрывает по запросу — опираясь на внутренние
нормативные документы (ВНД), финансовую отчётность, сигналы EWS и историю клиента, и при этом
**не выпуская чувствительные данные за периметр** организации.                        [VIS-001]

---

## Целевые сегменты и value proposition

- **Кредитный аналитик / риск-менеджер (Луидор)** → диалог по сделке вместо ручного сбора
  из форм и внешних инструментов; вывод + раскрываемое рассуждение.                     [SEG-01]
- **Согласующие / андеррайтер / кредитный комитет** → короткое заключение как основа
  решения; детали и трассировка к источнику доступны по запросу.                        [SEG-02]
- **Комплаенс / владелец ВНД** → проверка соответствия ВНД и явное выделение
  факторов нестандартности прямо в чате.                                                [SEG-03]

## Цели и North Star метрики

| id      | Цель                                             | North Star метрика                                              | trace_up |
|---------|--------------------------------------------------|----------------------------------------------------------------|----------|
| GOAL-01 | Сократить цикл анализа сделки                    | Время до заключения по сделке ≤ X мин (baseline — ручной день) | Приоритет №1: «чат по сделке» |
| GOAL-02 | Доверие через объяснимость                       | % заключений, принятых аналитиком без ручной переработки       | «короткое заключение, полное по запросу» |
| GOAL-03 | Закрыть утечку данных в публичную модель         | Число обезличенных выгрузок в публичный ChatGPT → 0            | «клиент уже обезличивает и шлёт в ChatGPT» |
| GOAL-04 | Покрытие сигналов риска                          | % сделок с авто-подсветкой EWS / историчности / нестандартности| кейс банкрота, кейс «кинул банк 5 лет назад» |

> **North Star (кандидат):** доля сделок, по которым короткое заключение агента принято
> аналитиком без ручной переработки. Развилка «время vs доля принятых» — в открытых вопросах.

## Принципы и ограничения (non-negotiable)

- **Саммари → детали.** Короткий вывод сверху, полное рассуждение доступно раскрытием, а не
  вырезается. Это разрешает конфликт «коротко» ↔ «не резать рассуждение».                [PRIN-01]
- **Данные не покидают периметр.** Свой агент вместо публичной модели — закрывает доказанный
  спрос и текущую утечку одновременно.                                                   [PRIN-02]
- **Объяснимость и трассируемость.** Каждый вывод привязан к источнику: ВНД, отчётность,
  сигнал, эпизод истории.                                                                [PRIN-03]
- **Пространство на рассуждение.** Агенту оставляется место рассуждать; жёстко не сокращать
  («если сокращать → плохо»).                                                            [PRIN-04]
- **Диалог по конкретной сделке, не по формам.** Единица работы — сделка, а не форма.     [PRIN-05]
- **Ассистент, а не авто-решение.** Агент готовит заключение, решение остаётся за человеком/
  комитетом.                                                                             [PRIN-06]

## Тематический охват (вход для business-architecture — capabilities следующего этапа)

Не входит в видение как «что делаем как», но фиксируется как объём для следующего скилла:

- **Чат по сделке** (P0): саммари перед работой — кто/что/зачем, риски в обе стороны,
  плюсы/минусы, бенефициар. Не привязан к формам.                                        [SCOPE-01]
- **ВНД и нестандартность** (P0): соответствие ВНД (узкий список), явное выделение факторов
  нестандартности.                                                                       [SCOPE-02]
- **Финансовая отчётность**: расшифровки, ОСВ, анализ запасов, Excel; стресс CF-модели.   [SCOPE-03]
- **Сигналы и историчность**: EWS, таймлайн клиента и группы, подсветка исторических красных
  флагов.                                                                                [SCOPE-04]
- **Данные из интернета / отрасль**: рынок и конкуренты, отраслевые ТГ-каналы (автосводки
  вместо ручных скринов), сводки по отчётностям ритейлеров.                              [SCOPE-05]
- **Контракты и вложения**: Q&A по контрактам, суммаризация длинных доков (300 стр.),
  пояснение коротких непонятных (в т.ч. ЮЗ).                                             [SCOPE-06]
- **Справка / вики-режим**: объяснение терминов (напр. DSCR).                            [SCOPE-07]

## Non-goals (что продукт сознательно НЕ делает на этом этапе)

- Не строим работу вокруг форм — единица работы — сделка.
- Не автоматизируем принятие решения по сделке (одобрение остаётся за человеком/комитетом).
- Не заменяем публичный ChatGPT «в лоб» без контура безопасности — смысл именно в периметре.
- Не резюмируем жёстко в ущерб рассуждению (следствие PRIN-01/PRIN-04).

## Допущения и открытые вопросы

- **Узкий список ВНД** назван, но не получен — нужен перечень документов и их формат.       [Q-01]
- **Доступ к данным сделки** (отчётность: ОСВ, расшифровки; таймлайн клиента/группы;
  вложения) — объём и способ доступа уточнить.                                            [Q-02]
- **Развилка North Star**: оптимизируем «время до заключения» или «долю принятых заключений»?
  Влияет на приоритеты команды.                                                           [Q-03]
- **Развилка PRIN-01 ↔ PRIN-04** (коротко ↔ не резать рассуждение) — проговорить явно с
  командой, иначе метание. Разрешается схемой «саммари → детали».                         [Q-04]
- Формат «периметра» (self-hosted модель / приватный контур) — вход для `it-architecture`. [Q-05]

## Наблюдения (для встречи / для Марка)

- **Приоритет клиента совпал с продуктовым сюжетом.** «Первое, что бы сделал — чат по сделке»
  + «короткое заключение, полное по запросу» = ровно лестница «саммари → детали». Аргумент на
  встрече: это первый запрос пользователя, а не наша выдумка.
- **P0-развилка зафиксирована** ([Q-04]): клиент хочет одновременно сжатый вывод и неурезанное
  рассуждение — это не баг, а требование к UX «саммари → детали».
