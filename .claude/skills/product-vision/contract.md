# Handoff-контракт (Product Vision)

Каждый элемент выхода оформляется как запись базового handoff-контракта. На уровне Vision
родительского артефакта в цепочке ещё нет, поэтому корневые элементы используют `trace_up: ROOT`.

| Поле | Назначение |
|------|------------|
| `id` | Уникальный идентификатор (`VIS-001`, `PAIN-001`, `SEG-001`, `GOAL-002`, `MET-001`, `PRIN-001`, `NOGOAL-001`) |
| `type` | vision / pain / segment / goal / metric / principle / non_goal / assumption / question |
| `text` | Содержание элемента |
| `trace_up` | Связь вверх: `ROOT` (или `CONST-*`, когда появится constitution-скилл) |
| `source` | Внешний источник/provenance: стратегия, рынок, регулятор, исследование, интервью |
| `status` | draft / approved |
| `owner` | Кто approve (стейкхолдер) |
| `version` | Версия артефакта |

## Правила

- `source` фиксирует происхождение данных и **не подменяет** `trace_up`.
  `trace_up` — это внутренняя связь вверх по цепочке артефактов, `source` — внешний провенанс.
- Корневые элементы (`vision`, `principle`) ссылаются на `ROOT`. Производные элементы
  (`pain`, `segment`, `goal`, `non_goal`) ссылаются на `VIS-001`; `metric` — на свой `goal`.
- Присвоенные `id` далее используются в `business-architecture` как значения `trace_up`
  и в матрице трассируемости валидатора.
- Для записей `assumption` / `question` дополнительно указывается `severity`
  (blocker / warning / info); для `assumption` — ещё уверенность `<XX%>` и способ проверки
  (см. шаблон в [templates.md](templates.md)).
- Идентификаторы нумеруются тремя цифрами: `-001`, `-002`, … (единый формат во всех артефактах).
