# Evaluations — it-architecture

Сценарии для проверки скилла по методике Anthropic (evaluation-driven development).
Прогонять на Haiku, Sonnet и Opus: что хорошо для Opus, может требовать больше деталей для Haiku.
Встроенного раннера нет — `expected_behavior` проверяется ревьюером/скриптом вручную.

## Eval 1 — базовый прогон (happy path, на входе выход business-architecture)

```json
{
  "skills": ["it-architecture"],
  "query": "На входе бизнес-архитектура продукта оценки рисков: CAP-001 сбор данных контрагента, CAP-002 расчёт скоринга, CAP-003 объяснение решения, CAP-004 мониторинг портфеля; REQ-001 оценка ≤5 мин для 95% заявок (nfr/latency), REQ-002 каждое решение с объяснением (func), REQ-003 ≥70% полей авто-заполняются (func); принцип PRIN-001 объяснимость обязательна. Спроектируй ИТ-архитектуру.",
  "files": [],
  "expected_behavior": [
    "Заполняет три слоя: application (APP-*), data (DATA-*), infra (INFRA-*)",
    "Строит capability→application mapping; каждая CAP-001..004 имеет статус covered или gap+action",
    "Каждая CAP-* со входа встречается в covers хотя бы одного компонента или mapping",
    "NFR-требование REQ-001 (latency) отражено в infra-слое через trace_up/covers",
    "Есть ≥1 ADR с альтернативами/обоснованием/последствиями и обязательный блок обратной связи наверх (feedback)",
    "У каждого элемента заполнены id/type/trace_up/source/covers(где применимо)/status/owner/version; вывод на русском, в таблицах"
  ]
}
```

## Eval 2 — неполный вход (скилл фиксирует пробелы, а не выдумывает)

```json
{
  "skills": ["it-architecture"],
  "query": "Спроектируй ИТ-архитектуру внутреннего инструмента. Текущий стек, оценки стоимости и владельцы пока неизвестны.",
  "files": [],
  "expected_behavior": [
    "Не выдумывает стек, оценки стоимости, сроки и владельцев — ставит <unknown>/<to validate>/<оценка>/<owner> или [H] гипотеза",
    "Недостающие данные выносит в «Допущения и открытые вопросы» как question/assumption с severity и status",
    "Сохраняет полный контракт полей даже при скудном входе",
    "Запрашивает максимум 2 критичных уточнения (например, целевой объём/SLA)"
  ]
}
```

## Eval 3 — покрытие capability (gap явно помечен)

```json
{
  "skills": ["it-architecture"],
  "query": "На входе CAP-001..CAP-005, но внешний источник данных для CAP-005 (обогащение санкционными списками) пока недоступен. Сделай capability→application mapping.",
  "files": [],
  "expected_behavior": [
    "Все покрытые capability помечает covered с указанием реализации (APP-*/DATA-*/INFRA-*)",
    "CAP-005 помечает статусом gap, а не выдумывает несуществующую реализацию",
    "Для gap указывает action (например, PoC интеграции / запрос источника)",
    "Поднимает gap в блок обратной связи наверх или в открытые вопросы с severity"
  ]
}
```

## Eval 4 — обратная связь наверх (петля plan → spec)

```json
{
  "skills": ["it-architecture"],
  "query": "Требование REQ-001 latency ≤5 мин конфликтует с принципом PRIN-001 объяснимость: объяснимая модель медленнее. Как поступить?",
  "files": [],
  "expected_behavior": [
    "Фиксирует конфликт реализуемости в блоке feedback с target на REQ-001/PRIN-001",
    "Даёт recommendation наверх (например, пересмотреть порог latency или приоритет объяснимости)",
    "Не меняет требование или принцип самостоятельно — только предлагает наверх",
    "Присваивает feedback severity и status; при необходимости оформляет ADR с альтернативами"
  ]
}
```

## Eval 5 — отказ от чужой высоты (anti-scope)

```json
{
  "skills": ["it-architecture"],
  "query": "Спроектируй ИТ-архитектуру, заодно перепиши North Star метрику и сразу напиши код сервиса скоринга с тестами.",
  "files": [],
  "expected_behavior": [
    "Формирует только технический план: application/data/infra, mapping, ADR, roadmap, feedback",
    "Не переписывает видение/метрики/capability — указывает, что это product-vision / business-architecture (только через feedback наверх)",
    "Не пишет код и задачи реализации — указывает, что это нижний этап SDD (Tasks → Implement)",
    "Объясняет, что выход (APP-*/DATA-*/ADR-*) передаётся дальше по цепочке SDD в скилл-валидатор"
  ]
}
```
